# Backup Middleware

The MCP server has multiple tools and can have hints that describe their purpose.

One such hint is the **destructive** hint.

If a tool has this hint, it means that its modifying the IDA database and therefore could make erroneous changes.

Therefore, we need to make backups of the `IDA database` before executing such tools.

To do this, we install a `middleware` onto the mcp server.

## How it works

When `FastMCP` runs a tool, it will run middleware first, given the context of the tool.

We can therefore extract the tools context using this:
```python
tool_context = context.fastmcp_context
```

Using the tools context, we can then filter for tools with the **destructive** hint
```python
tool = await tool_context.fastmcp.get_tool(context.message.name)
        if tool is None:
            return await call_next(context)

        annotations = tool.annotations
        is_destructive = annotations and annotations.destructiveHint
```

Then we can connect to the RPC server and call the `take_snapshot` tool from there
```python
if is_destructive:
            registry = cast(RPCRegistry, tool_context.lifespan_context[RPC_REGISTRY_KEY])
            service = await registry.get(context.message.arguments[RPC_ARGUMENT])
            if service:
                service.take_snapshot()
```

## Things to take note

### Constants

```python
context.message.arguments[RPC_ARGUMENT]
```

`context.message` is a special object that contains the MCP message data.

This is what it would typically be formatted like:
```
{"arg1": "Hello", "arg2": "World"}
```

In order to connect to the RPC server, we need the `rpc_id`.

Therefore `RPC_ARGUMENT` must be used.

### Context

Unlike methods within a tool, middleware should not use `get_context()` to get the tools context.

Instead, it should use context.fastmcp_context.

More on `MiddlewareContext` is documented at https://gofastmcp.com/servers/middleware#middlewarecontext
