# ChatSession & ChatbotHandler

## ChatSession

- Should live outside of the UI components
- Holds both the UI messages and the backend turn-by-turn session

Two fields, nothing else:

- `messages: list[Message]` — what the UI replays
- `chat_session: CompactingSession` — what the LLM sees

Two methods:

- `add_message(msg)`
- `append_to_last_message(msg)`

### UI messages

Just a list of `Message`s (the class).

A new `MessageColumn` adds a new `Message` to the list.

After that, only paragraphs get added to it. The `MessageColumn` manages the
content.

Paragraph text is concatenated straight into that one `Message.content`, joined
with `"\n\n"`.

<Callout>
The merge happens **while the response streams**, not when the window closes.
By the time `load_message_history()` runs there is already one `Message` per
column, so each column reloads as a single `MessageParagraph`.
</Callout>

### Backend session

`CompactingSession` subclasses `SQLiteSession` from the Agents SDK.

`db_path` is `":memory:"`, so history lives in RAM and dies with the process.

It overrides `add_items()` to compact once the session outgrows a threshold.

The compaction:

1. `threshold = 10` items, `keep_last_n = 5`
2. Everything before the last 5 is the head, the last 5 is the tail
3. The head is summarised by a summarizer agent (`max_turns=1`)
4. The session is cleared
5. `[compacted_summary, *tail]` is written back

The summary goes back in as a `system` message.

The summarizer comes from `get_compacting_agent()`.

### What actually persists

<Callout type="warning">
`CompactingSession` is a local in-memory store. A fresh provider client and
`Agent` are built **per turn** inside `ChatBotTask.run()`.

What survives closing the window is the *history*: `ChatSession.messages` for
the UI and the SQLite rows for the LLM. Plus the `MCPClient` connection, which
is owned elsewhere.

Persistence of state, not of a socket.
</Callout>

## ChatbotHandler

This is where the `ChatSession` lives.

It is an `ida_kernwin.action_handler_t`, registered as a context menu item. Only
shows up on pseudocode views (`BWN_PSEUDOCODE`).

It does **not** create the `MCPClient`. `AetherUIHooks` creates one and passes it
in, shared with the annotator.

`activate()`:

1. Builds a `ChatbotPanelForm` with the session and the MCP client
2. `Show()`s it with `WOPN_RESTORE`
3. Docks it `DP_RIGHT` of the widget that was focused

If something needs to be persistent even after the window closes, instantiate it
here.

## ChatbotPanelForm

The `ida_kernwin.PluginForm` between the handler and the panel.

- `OnCreate` — wraps the IDA form as a `QWidget`, calls
  `create_chatbot_panel(session, mcp_client, parent)`
- `OnClose` — calls `chat_panel.shutdown()`, which cancels every in-flight task

The session is not touched on close. That is the whole point.
