# StyledComponent & Plugins

## StyledComponent

- A `QWidget` with the ability to add on plugins
- Plugins let `QWidget`s use composition and not just inheritance

Strictly it extends `AbstractComponentPluginManager`, which is the `QWidget`.

See [Component Plugins](/development/gui/component-plugins) for writing one.

### Default plugins

<Callout>
`ThemePlugin` and `JinjaPlugin` are installed on **every** `StyledComponent`,
before anything you pass in.

`FontPlugin` is not. Pass it explicitly: `super().__init__(parent,
plugins=[FontPlugin()])`.
</Callout>

### Lifecycle

Five phases, in order:

1. `setup()` — early init, before any widgets exist
2. `init_ui()` — abstract, build the widget tree
3. `_install_plugins()`
4. `plugins_ready()`
5. `teardown()` — on `closeEvent`, before plugins uninstall

All the chatbot components use `setup()` to declare their attributes and
`init_ui()` to build.

### self.state

How plugins manage state inside a `StyledComponent`.

<Callout type="warning">
It is a `defaultdict(lambda: None)`, not a plain dict.

Missing keys come back as `None` instead of raising `KeyError`, so a typo in a
template fails quietly.
</Callout>

Populated before your code runs:

- `state["theme"]` — `"light"` or `"dark"`
- `state["colors"]` — a namespace of `QPalette` roles

`FontPlugin` adds `state["fontstyles"]`. So changing the font state means
writing `widget.state["fontstyles"]`.

### Jinja hooks

Override any of these to style or template the widget:

- `styles()` — inline QSS template string
- `style_file()` — path to a `.qss.jinja`
- `template()` / `template_file()` — same, for HTML
- `render_html(**context)` — renders it. `colors` and `theme` are reserved.

`_apply_styles()` re-renders the QSS and is called by `ThemePlugin` before
`on_theme_change()`.

<Callout type="warning">
**DO NOT TOUCH:** the `StyledComponent` class is sacred (kinda).

Every AETHER GUI component is a child of it. Changes may not break everything,
but do not touch it unless absolutely necessary and with express permission.

This is to prevent breaking someone else's code, since it is a very important
shared class.
</Callout>

## Font Plugin

- The plugin that all text-based components instantiate
- Updates the `"fontstyles"` object in the component's state to the new `QFont`
- In a stylesheet, use `{{ fontstyles.size }}` and `{{ fontstyles.family }}`
- More in the [Font Plugin](/development/gui/plugins/font-plugin) docs

You must pass the parent component to the child widget. The plugin walks up
`parentWidget()` looking for the window the component belongs to.

Components react by overriding `on_font_change(font)`. In the chatbot that
always means re-measuring height.

## Other plugins

Pretty standard and should not be touched.

Just know that they work.
