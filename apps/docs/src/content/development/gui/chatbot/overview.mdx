# Chatbot Overview

This guide explains how the chatbot's UI, background tasks, and conversation history fit together.
For setup and everyday use, start with the GUI user guide.

The AETHER chatbot is built using the following parts:

1. **GUI and Rendering**: the GUI widgets live under `features/chatbot/components`. `ChatbotAreaRenderer` writes into them.
2. **Orchestrator**: constructed by the chatbot panel, it runs on IDA's main thread. 
At the start of each turn it submits context retrieval and agent tasks to the shared `WorkerManager`, then routes streamed output back to the renderer on the main thread.
3. **Agent**: built in `backend/chatbot/task`. Streams the provider's output, renders the prompts from `task/content`, and wraps each MCP tool so the model can call it.
4. **Session**: `ChatSession` in `utils/chat_session` holds UI messages and a `CompactingSession`. The Agents SDK provides an in-memory SQLite database for model history; compaction summarises older items.

Source paths on these pages are relative to `apps/gui/src/aether_gui/`, unless stated otherwise.

## Session and lifecycle

`ChatbotHandler` is the entry point, a context-menu action on pseudocode views. 
It owns the `ChatSession` and opens the panel. 
Because the session lives on the handler rather than the window, it survives closing and reopening the panel while that handler remains alive. History is not restored after restarting IDA.

`ChatSession` holds two things:

- **UI messages**: replayed to redraw the conversation when the window reopens.
- **A `CompactingSession`**: the turn-by-turn history the LLM sees.

`CompactingSession` subclasses the Agents SDK's `SQLiteSession` and lives in
`packages/utils/src/aether_utils/compacting_session/`. By default, once history exceeds
10 items, it summarises older items and retains the latest five, extending that tail
when needed to keep tool calls with their results. These are history items, not whole
user turns. If summarisation fails, the original history is kept.

Compaction affects model history only; the visible conversation remains intact.
`ChatSession` also appends a text log to `chat_sessions/<rpc_id>.log` under the GUI's
application data directory. This log is not loaded to restore a session.

## A turn, end to end

1. **Submit**: The panel displays the user's message and disables further submissions until the turn finishes.
2. **Offload**: `ChatOrchestrator` reads the current address and RPC ID, then requests context through the Model Context Protocol (MCP) server. It passes the resulting future and the prompt to `ChatBotTask`. Tasks run on `WorkerManager`'s shared background event loop.
3. **Run**: The task waits up to 30 seconds for context, builds the agent, and streams the response. The agent can call MCP tools, which may use remote procedure calls (RPC) to read or modify the open IDA database.
4. **Render**: Consumer threads forward output to IDA's main thread. The renderer creates a bubble (`MessageColumn`), adds a paragraph (`MessageParagraph`), or appends streamed text to the current paragraph.

See Orchestration for prompts, tool calls, and rendering rules.

To cancel a turn, close the chatbot window; there is no separate stop button.
Closing requests cancellation of the panel's outstanding tasks and suppresses further UI callbacks.
The `ChatSession` survives, but cancellation does not undo changes already made by tools.

## Configuration

A chatbot turn requires a non-empty provider API key. `OpenAIGateway.get_model()` raises
`ValueError` if it is missing. Configure the provider in **Edit → Plugins → AETHER Settings**;
see Configuration for the available fields.

| Key | Read by | Notes |
| --- | --- | --- |
| `provider.api_key` | `OpenAIGateway` | Required. |
| `provider.gateway_url` | `OpenAIGateway` | The OpenAI-compatible endpoint. |
| `provider.models` | `OpenAIGateway` | Name to model-id map. |
| `provider.default_model` | `OpenAIGateway` | Always what the chatbot resolves to. |
| `tls.client_cert_path`, `tls.client_key_path` | `OpenAIGateway` | Optional client certs. |
| `mcp_url` | `MCPClient` | Where the MCP server lives. |
