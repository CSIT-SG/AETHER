The AETHER chatbot is built using the following parts:

1. **GUI and Rendering**: widgets created under `features/chatbot/components`, and `ChatbotAreaRenderer` writes into the widgets.
2. **Orchestrator**: constructed by the chatbot panel, runs on IDA main thread. At the start of each turn submits agent task to WorkerManager, and routes streamed output back to renderer.
3. **Agent**: built in `backend/chatbot/task`. Streams the provider, renders prompts from `task/content`, and wraps each MCP tool so the model can call it.
4. **Session**: `ChatSession` in `utils/chat_session` holds UI messages and a `CompactingSession`. Agent SDK provides SQLite storage and we provide compaction.

## Session and lifecycle

`ChatbotHandler` is the entry point — a context-menu action on pseudocode views. 
It owns the `ChatSession` and opens the panel. 
Because the session lives on the handler and not the window, it survives the chatbot being closed and reopened, and dies only with the IDA process.

`ChatSession` holds two things:

- **UI messages** — replayed to redraw the conversation when the window reopens.
- **A `CompactingSession`** — the turn-by-turn history the LLM sees.

`CompactingSession` subclasses the Agent SDK's `SQLiteSession`. 
Once history grows past a threshold it summarises the oldest turns and keeps the rest. 
That compaction is our code, not the SDK's.

## A turn, end to end

1. **Submit**: User sends their prompt. The panel draws their own message first, before other tasks proceed.
2. **Offload**: `ChatOrchestrator` gathers current IDA context, package with prompt to become task for `WorkerManager`. Main thread is freed.
3. **Running**: On worker thread, agent is built with provided prompt and context and provide MCP tooling. 
Streams provider output and calls MCP tools as needed. MCP is a separate layer designed to give convinient tooling, and chatbot is one of the consumers. 
A tool may call RPC to read/write into IDA idb, and returns its output to the agent. No UI involved.
4. **Render**: Agent streaming, tool input, and tool output are processed at worker. 
Each piece is pushed to main thread and renderer draws what is new: a new bubble (`MessageColumn`), a new paragraph (`MessageParagraph`), or text appended within the paragraph during streaming.

Only way to cancel during a turn, for now, is to close the window during a task. The `ChatSession` containing history survives.

## Configuration

The chatbot will not start without a provider API key — `OpenAIGateway` raises
`ValueError`. See the Configuration page for the file itself.

| Key | Read by | Notes |
| --- | --- | --- |
| `provider.api_key` | `OpenAIGateway` | Required. |
| `provider.gateway_url` | `OpenAIGateway` | The OpenAI-compatible endpoint. |
| `provider.models` | `OpenAIGateway` | Name to model-id map. |
| `provider.default_model` | `OpenAIGateway` | Always what the chatbot resolves to. |
| `tls.client_cert_path`, `tls.client_key_path` | `OpenAIGateway` | Optional client certs. |
| `mcp_url` | `MCPClient` | Where the MCP server lives. |
