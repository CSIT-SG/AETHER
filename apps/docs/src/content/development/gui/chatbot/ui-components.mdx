# UI Components

![Anatomy of the ChatbotPanel](/chatbot-panel-anatomy.png)

Every component here is a `StyledComponent`, except `ButtonComponent`.

The widgets nest: `ChatbotPanel` holds the `MessageArea`, which holds
`MessageColumn` bubbles, each holding one or more `MessageParagraph`s.

## ChatbotPanel

- The window spawned by the `ChatbotHandler`
- Should hold no backend bridge logic beyond wiring `ChatInput` to the
  `MessageArea` and constructing the `ChatOrchestrator`
- Extremely susceptible to prop drilling, so be conscious of that when adding
  features

It draws the user's own message, starts the turn, replays history when the window
reopens, and cleans up on close.

## MessageArea

Where all messages are placed: user, LLM, and tool output.

### The three important backend functions

The `ChatAreaProtocol` surface.

- `add_new_message_column()`
- `add_paragraph_to_last_column()`
- `append_to_last_paragraph_of_last_column()`

<Callout type="warning">
Call these on IDA's main thread — the widget belongs to IDA's GUI thread.
</Callout>

## MessageColumn

The actual message bubble. Separates user from LLM messages, holds multiple
`MessageParagraph`s, and is built as header, body, footer.

Layout differs by role: `USER` is right-aligned, `AETHER` (llm) is centred. The footer holds
the copy button.

## MessageParagraph

One block of rendered Markdown — a `StyledComponent` wrapping a `QTextBrowser`,
with `FontPlugin` so it tracks IDA font changes.

<Callout type="warning">
Be conscious of when you re-render. Re-rendering one paragraph forces Qt to
re-lay out **every** message in the conversation.

So the cost scales with conversation length, not paragraph size — and it happens
once per streamed delta, on the IDA main thread.
</Callout>

<Callout type="warning">
Be careful adding `StyledComponent`s inside a message. Every one is part of that
re-layout, and each installs its own theme and font plugins on construction and
re-renders its QSS on theme changes.

So per-message widgets — badges, buttons, inline controls — multiply the cost:
Qt reprocesses the whole conversation on every delta. Keep the per-message tree
small.
</Callout>

## Message

The naming is a bit confusing, but it is just content plus metadata: `id`, `role`,
`content`, `timestamp`.

`MessageRole` is only `USER` or `AETHER`. There is no tool role — tool call input
and output both render as `AETHER`, since the calls are the llm's.

## ChatInput

- A `QTextEdit`, not a line edit, so it grows with the text
- Ctrl+Enter submits, so does the button
- Emits `submitted(str)`, which the panel connects to
- Clears and refocuses after submit

## Search

Ctrl+F. Split across three components: `SearchBar` (the input and controls),
`MessageArea` (finds matches and tracks the current one), and `MessageParagraph`
(highlighting).

## ScrollBar

<Callout type="warning">
Unfinished migration. `ScrollBar` is exported but nothing constructs it —
`MessageArea` styles the raw `QScrollBar` through the `ChatScrollBar` object name
instead.
</Callout>

## ButtonComponent

Current use copy button in each message footer. A plain `QPushButton`.
