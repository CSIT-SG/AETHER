# Getting Started

You should install one of of our clients (CLI or GUI) to use AETHER. You also need to set up and configure an LLM gateway to use AETHER.

## System Requirements

- Operating System: Windows or Linux
- Python: `3.12` or `3.13`

<Callout type="warning">
  Python 3.14 is not supported by IDA Pro due to compatibility issues with
  `PySide6`.
</Callout>

- IDA Pro: Version `9.2` or later
- LLM Gateway: You need a openai-compatible LLM gateway and api key to use Aether. The default is OpenRouter, but you can configure your own provider in the [configuration file](./configuration).

## Graphical User Interface (GUI)

Download the release binaries.

1. In the [repository](https://github.com/csitgovsg-acube/AETHER-next) click on `Releases`
2. Click on latest release
3. Download `aether_gui-v<version>.zip`

<Callout type="warning">
  The GUI plugin runs inside IDA's embedded Python, so its dependencies must be
  installed into the **same** Python that IDA uses. Point IDA at a Python `3.12`
  or `3.13` install with `idapyswitch` (ships with IDA), then run the install
  script below with that same interpreter.
</Callout>

4. Run the prod script.

```bash
python install_prod.py
```

This will install the wheel bundles and copy the plugin entrypoint into the IDA plugins folder.

You can install into a custom plugins folder with the `--plugin-path` argument. It defaults to `%APPDATA%\Hex-Rays\IDA Pro\plugins` (Windows) or `~/Hex-Rays/IDA Pro/plugins` (Linux), eg. `python install_prod.py --plugin-path "D:\ida-plugins"`.

5. Start the backend server.

```bash
python run_prod_backend.py
```

You will need to keep the backend server running in the background as this bridges the RPC layer with the GUI instance.

## Headless Command-Line Interface (CLI)

Download the release binaries.

1. In the [repository](https://github.com/csitgovsg-acube/AETHER-next) click on `Releases`
2. Click on latest release
3. Download `aether_cli-v<version>.zip`
4. Run the install script.

```bash
python install.py
```

This will install the wheel bundles. Afterwards, you can run `entrypoint.py` with your IDA database path and the install directory of **IDA**.
You can also pass in the host address to run the **CLI** on.

For example:

```bash
python entrypoint.py --idb C:/path/to/your/idb/example.exe.i64 --ida-dir "C:/Program Files/IDA Professional 9.2"
```

You can then use the output port to [connect your agent](https://modelcontextprotocol.io/) to the MCP server.

## Setting up an LLM Gateway

Choose from any OpenAI-compatible LLM gateway. You should target at least a 7B parameter model for average performance.

### OpenRouter

Choose a model on [OpenRouter](https://openrouter.ai/) and generate an API key. Then your config will look like:

```json
{
    "provider": {
        "gateway_url": "https://openrouter.ai/api/v1",
        "api_key": "YOUR_API_KEY",
        "models": {
            "claude-sonnet-5": "anthropic/claude-sonnet-5",
            "qwen3.5-9b": "qwen/qwen3.5-9b"
        },
        "default_model": "claude-sonnet-5"
    },
    ...rest of your config
}
```

### llama.cpp (llama-server)

Follow their [install guide](https://github.com/ggml-org/llama.cpp#quick-start) to set up a `llama-server` instance.

For example, running the following command will start a `llama-server` instance with [huggingface's `Qwen2.5-7B-Instruct-GGUF`](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct-GGUF) model on port `8080`:

```bash
llama-server -hf bartowski/Qwen2.5-7B-Instruct-GGUF:Q4_K_M
```

Then your config will look like:

```json
{
  "provider": {
      "gateway_url": "http://localhost:8080/v1",
      "api_key": null,
      "models": {
          "qwen-7b": "bartowski/Qwen2.5-7B-Instruct-GGUF:Q4_K_M"
      },
      "default_model": "qwen-7b",
      "extra_body": null
  },
  ...rest of your config
}
```

If you need to support authentication, generate an API key on the `llama-server` instance and set it in your config in `provider.api_key`.

### LiteLLM

Install LiteLLM by following their [installation guide](https://docs.litellm.ai/docs/#litellm-proxy-server-llm-gateway).

Then run a server.

```bash
litellm --model huggingface/bartowski/Qwen2.5-7B-Instruct-GGUF:Q4_K_M
```

You should set the API key in the config to match the one you created. Then your config will look like:

```json
{
  "provider": {
      "gateway_url": "http://localhost:4000/v1",
      "api_key": "YOUR_API_KEY",
      "models": {
          "hf-qwen-7b": "huggingface/bartowski/Qwen2.5-7B-Instruct-GGUF:Q4_K_M"
      },
      "default_model": "hf-qwen-7b",
      "extra_body": null
  },
  ...rest of your config
}
```

## How to use AETHER (GUI)

Once you have successfully installed the GUI plugin and set your API key. Follow the steps below to start using AETHER.

1. Start the backend server
2. Start IDA Pro and open a binary
3. Press `tab` to open the `decompile view` in IDA Pro
4. Right click anywhere in the `decompile view` to open the context menu
5. Click on the `AETHER-next` dropdown to access the functions of AETHER.
   <Callout type="info">
     NOTE: AETHER is only accessible from the `decompile view`.
   </Callout>

### Annotator

The Annotator is a tool that enhances readability of decompiled code. It does this by adding comments, renaming variables and renaming functions.

The Annotator will analyse the decompile code starting at the **current function on screen** and add the annotations.

![Annotator](/annotate.png)

#### Usage:

1. Right click **anywhere** in the `decompile view` to open the context menu
2. Click on the `AETHER-next` dropdown
3. Click on `Annotate Function` to start the annotation process.

### Struct Manager

The Struct Manager is comprised of the `create` and `re-evaluate` functionalities. This aids the creation of structs in the reverse engineering process.

The Struct Manager will look at the **highlighted variable** in the decompile view and create a struct for it.
It takes into account the context in which the variable exists and that which it's function is called. Using this information, it will generate a struct that is most likely to be correct.

<Callout type="info">
  NOTE: you __MUST__ highlight a variable to use the struct create and
  re-evaluate functionalities.
</Callout>

![Struct Manager](/struct_manager.png)

#### Usage(create):

1. Highlight a variable in the `decompile view`
2. Right click to open the context menu
3. Click on the `AETHER-next` dropdown followed by the `struct manager` dropdown
4. Click on `Create Struct` to start the struct creation process.

#### Usage(re-evaluate):

1. Highlight a variable in the `decompile view`
2. Right click to open the context menu
3. click on the `AETHER-next` dropdown followed by the `Manage Struct` dropdown
4. Click on `Re-evaluate Struct` to start the struct re-evaluation process.

### Chatbot

The Chatbot is a tool that allows you to interact with the decompiled code in a conversational manner.
You can ask questions about the code, request explanations, or seek guidance on specific functions or variables.

The Chatbot also has access to the `annotator` and `struct manager` functionalities. This allows you to request for annotations or struct creation directly from the chatbot.

![chatbot](/chatbot.png)

#### Usage:

1. Right click **anywhere** in the `decompile view` to open the context menu
2. Click on the `AETHER-next` dropdown
3. Click on `Open AI Chatbot` to open the chatbot window.
4. type your prompt into the input box, press `enter` to create new lines and `ctrl + enter` to send the prompt to the chatbot.

![chatbot window](/chatbot_window.png)

## Development

Clone the repo and run the gui dev script.

```bash
git clone https://github.com/csitgovsg-acube/AETHER-next
cd AETHER-next
uv sync --all-packages
cd apps/gui && uv run python ./scripts/install_dev.py
```

This will install the required dependencies for idapython and link the plugin entrypoint into the IDA plugins folder.

Start the backend server.

```bash
cd packages/backend
uv run python ./scripts/run_headless.py
```

<Callout type="info">
  Ensure that AETHER backend is running in the background as this bridges the
  RPC layer with the GUI instance.
</Callout>

Follow the workspace README files for more information.
